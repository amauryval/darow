**How much to write.** An entry may be long. Detail is welcome here — it is what makes the chantier
implementable months later, by someone with no memory of the audit that found it: name the files and
the components concerned, say what to change and in what order, state the rules and invariants to
respect, and record the trap that produced the gap. Naming what exists is part of that: a component,
a composable, a type, a prop or an event are cited by name — that is a pointer into the code, not
code. Cite the file and the symbol, never a line number: it is stale the next time anyone touches
the file, and a wrong line sends the reader to the wrong place with confidence. A symbol is found by
search and stays true. What stays out is **code itself**: no snippet, no template fragment, no diff. Write the
instruction, not the patch — the code is written later, against the code as it is then.

**Every chantier here is responsive**, on the same terms as the rest of the UI, and lands only once
`mise run ui-build` (type-check) and `mise run ui-lint` pass — a type error is part of the chantier,
not a follow-up.

| TODO-F39 | The application never authenticates anybody: `client/session.ts` reads the server's `GET /session`, which described a caller a reverse proxy had already identified, and `useSession` offers `signIn`/`signOut` as full navigations to the gateway's own pages. The server now verifies OIDC bearer tokens itself (`../back/todo.md` TODO-27), so **the browser owns the login** and this layer has to acquire a token, send it, refresh it and drop it. Add `oidc-client-ts` (no Vue wrapper — the library is framework-free and a wrapper would hide the storage decisions below) and build four pieces. (1) `client/auth.ts` **replaces** `client/session.ts`: `getAuthConfig` over `/auth/config` and `getAuthSession` over `/auth/session`, both through `http.ts` like every other call — rule 0.1 has no exception for authentication, and the reference implementation's raw `fetch` on those two URLs is the one thing not to copy. Their DTOs go in `types.ts` with every other DTO and are the **only ones in this client that are not camelCase**: the module serializes `issuer_url`, `client_id`, `scopes`, `logged_in`, `authorized`, `roles`, `user`, and the nested user is `Provider`/`ID`/`Roles` — Go field names, the struct carrying no JSON tags. Comment that on the type: renaming those keys into house style is a silent `undefined` at runtime, which reads as "nobody is logged in". `Session` and its `canWrite`/`groups`/`loginUrl`/`logoutUrl` fields go. (2) `auth/oidc.ts` — the `UserManager` and nothing reactive: built from `/auth/config` and skipped entirely when any of the three fields is empty (demo mode, where there is no provider and no login control to show), `response_type: 'code'`, `loadUserInfo: true` (`pocketid` puts its roles in UserInfo, not in the access token), `automaticSilentRenew`, and **both** stores on `sessionStorage` — the user store holds the tokens, the state store holds the PKCE verifier across the redirect, and moving one without the other is half a fix. The `redirect_uri` is `/ui/auth/callback`: this SPA is served under a base path (`createWebHistory('/ui/')`, Vite `base`), so the callback path is built from that base and not from the router path alone, and it is the exact URL to register at the provider. Per-tab tokens cost the two things users expect, and both are bought back here: a boot recovery — a top-level `signinRedirect({ prompt: 'none', state: <return path> })` — gated on a non-secret `localStorage` flag saying "someone is signed in on this browser", set on a successful callback and cleared on logout and on a failed renewal, plus a second `sessionStorage` gate so a user the provider grants no role does not redirect forever; and a `BroadcastChannel` every tab listens on to drop its user on a logout elsewhere. The recovery never runs on the callback route itself. (3) `composables/useAuth.ts` — the lifecycle and the shared state, declared at module level and documented as the exception rule 0.11's neighbour allows (`useToast`, `useSettings` are the precedent): the session read from `/auth/session` cached for a few tens of seconds **keyed by the token** so a re-render never refetches it, the profile read from the **ID token** (`user.profile.name`, then `preferred_username`, then `email`) — the access token carries no name at all, which is why the display name cannot come from `/auth/session` — `signIn`, `signOut`, and the three events: `addUserLoaded` refreshes the session, `addAccessTokenExpired` and `addSilentRenewError` drop it and warn through `useToast` (a renewal that fails is usually a session ended somewhere else). `signOut` reads the user **before** removing it and passes its `id_token` as `id_token_hint` to `signoutRedirect`: without the hint the provider cannot tell which session to end and shows an account picker, which is a logout button that logs nobody out, and clearing the stored user first is exactly what throws the hint away. (4) `http.ts` gains the bearer header on every request, from a token the auth layer sets and clears — one owner, set when the session loads, cleared on logout and on expiry (rule 0.12) — and a third French status phrase for the `503` the server answers when the policy is unavailable, beside the `401`/`403` pair already there. A `401` on any call drops the token and asks for a re-check through a callback the auth layer registers, never an import of a composable into the transport. Wiring: `main.ts` builds the manager and runs the boot recovery **before** `mount`, so the first frame already knows whether anyone is signed in and no control flickers from enabled to disabled; a failed `/auth/config` leaves the application usable with no login control rather than blocking the mount, exactly as `useSession`'s failed probe does today. `router.ts` gains `/auth/callback` → `views/AuthCallbackView.vue`, whose job is to await `signinRedirectCallback`, return to the path the `state` carried, treat `login_required`/`interaction_required`/`consent_required` as an ordinary "not signed in" (clear the flag, go back to the page asked for) rather than an error, and show a visible message plus a watchdog — a stalled code exchange must never be a blank page. `useSession` is rebuilt on `useAuth` and keeps its name and its role as the single verdict the screen reads: `authenticated`, `roles`, the single display `role` label, `canWrite` = authorized **and** holding `admin`, and nothing else — a `guest` sits exactly where an anonymous visitor sits (`../back/todo.md` TODO-27), so the verdict is one role and not a list, mirrored once from the application role names the module returns and never from the provider's own names, which are mapped server-side and never reach the browser, `displayName`, and `enabled` false in demo mode. No route guard: every screen of this application reads, so guarding a route would lock a user out of a page the API serves them anyway; the verdict is spent on controls, not on navigation (TODO-F40). Ships with `mise run ui-build` and `mise run ui-lint` green; no vitest (rule 0.14), the transport's own test file excepted if the header lands in a path it covers. **On landing**: `spec.md` §2 (the client module list: `session.ts` → `auth.ts`, the snake_case exception, the token on every request), §4 (`useAuth` added, `useSession` rewritten), §9 (the boot-before-mount order, the callback route, the token's single owner, the per-tab storage decision), §11 (`views/AuthCallbackView.vue`, `auth/`), and `spec/index.md` | TODO | `spec.md` §0.1, §0.11, §0.12, §2, §4, §9, §11 |
