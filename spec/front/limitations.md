# Darow — Accepted limitations (Vue 3 UI)

> **Role** — what the `web/` admin application deliberately does not do. These are not defects to
> fix but scope decisions. A limitation that is lifted leaves this file and becomes an entry of
> [todo.md](todo.md).
> Neighbours: [blockers.md](blockers.md) ·
> [improvements.md](improvements.md) · [spec.md](spec.md) (rules and
> architecture).
>
> Go server: [../back/limitations.md](../back/limitations.md) · Project: [../project/limitations.md](../project/limitations.md).

Each entry carries a stable identifier (`LIM-Fn`); a retired identifier is never reused.

| # | Limitation | Consequence | Rule |
|---|---|---|---|
| LIM-F1 | [NEVER DO IT] No automated tests on the front: verification is manual, backed by the type-check (`mise run ui-build`) and the lint (`mise run ui-lint`) | No behavioural regression is caught by CI; `client/http.test.ts` remains the only net, over the HTTP transport | §0.14 |
| LIM-F3 | The geometry column is never a column of the data grid: a WKT literal is unreadable at cell width and the row endpoints do not serve it (back rule 7) | A geometry is read one row at a time, through the geometry modal, and edited on the map — never scanned down a column | §8.6 |
| LIM-F4 | Topology is held by shared vertices, not by set operations: two geometries follow each other because they hold the same coordinates, and only because of that | A limit that two rows overlap without sharing a vertex — a coverage that was never clean — is not repaired by editing it; the two sides move independently until they are snapped onto each other. In exchange the same mechanism works for lines and points as for polygons, which the set-operation recut never could, and nothing is ever rewritten behind the user's back | §8.8 |
| LIM-F7 | An edit session works on a **working set**, not on the whole table: it holds the geometries the pointer has reached, releases the untouched ones it has left behind or reached longest ago, and never says so. Nothing on screen announces what is editable | A geometry becomes editable by being pointed at, so its vertices appear under the pointer rather than being there in advance, and nothing distinguishes a geometry the session already holds from one it does not — that is deliberate: every row of the layer is a candidate, so "editable" is not information, and painting it over the rendering the user is reading would turn the screen into a status display. The cost is that whether a hover has landed is only told by the vertices appearing. It is also what keeps the `Modify` and the `Snap` interactive, since both index every vertex they are given, and what makes entering and leaving the mode instant |
| LIM-F5 | The map editor draws, reshapes, moves and carves holes; it does not split, merge, rotate, or undo a whole session — only the last click of the shape being drawn can be taken back, and a session is dropped whole or saved whole | A geometry is corrected, moved and a hole is cut on the map, but cutting one parcel into two is done elsewhere. What holds this back is no longer the geometry — the engine has the interactions for all of it — but the affordance: each is a gesture of its own in the bar | §8.8 |
| LIM-F8 | A drawn hole is checked for containment vertex by vertex, not edge by edge (`utils/holes.ts`) | A ring whose vertices all sit inside a concave polygon but whose edges leave and re-enter it is still accepted, and the resulting polygon is written as if it were valid. Catching that needs segment intersection, which the engine does not offer on a geometry and which no hand-digitized hole is likely to hit | §8.8 |
| LIM-F9 | A `TIMESTAMP` cell is a text field checked with `Date.parse`, not a date-and-time control: the server returns RFC 3339 with a zone (`2024-03-15T10:30:00Z`) and the browser's `datetime-local` cannot hold a zone, so round-tripping one through it would silently move the instant | The user types the timestamp by hand in the grid, and a wrong one is named before the save but never picked. `DATE` columns have the real control — their stored form (`AAAA-MM-JJ`) is exactly what `input[type=date]` round-trips | §8.2 |
| LIM-F11 | A shape drawn by mistake cannot be taken back on its own: closing it raises a draft row, and neither the shape nor that row can be dropped without dropping the whole session (*Annuler*). On a table without geometry the draft is dropped from the grid, since nothing was drawn for it | A single misplaced polygon costs every other reshape and every cell retyped since the session opened. It follows LIM-F5 — the session has no per-object undo — and lifting it means removing a feature from the edit layer and the draft that goes with it, in one gesture, on both halves at once | §8.8 |
| LIM-F12 | The size figures of §0.7 are a target, not a ceiling: a file that holds one subject stays whole even when it runs past them. Seven composables do today — `useEditLayer`, `useMapDraw`, `usePaginatedList`, `useEditTools`, `useWfsLayer`, `useRowEdits`, `useAuth` (`useSources` has since come back under the figure) | Length alone is not a finding and is not audited as one. What is still audited is §0.11 — one composable, one subject: a file grows past the figure because its subject is dense (the edit session's layer, its interactions), never because a second subject was added to it. Splitting a single subject across two files to meet a number costs more than it buys, the cross-file wiring being exactly what makes the session's state hard to follow | §0.7 |
| LIM-F2 | No i18n: the product is monolingual, every visible string is in French | Adding a language is a chantier of its own, not a setting | §0.17 |
| LIM-F6 | The WFS layer renders on the GPU, the MVT layer on a 2D canvas | The dense mode is the one left on canvas, which is the wrong way round — but the GPU vector-tile layer exposes no way to ask which feature is under a pixel, and §8.8 requires both a `pointer` cursor on hover and selection reversible in one click. Moving MVT to the GPU costs those two, or costs a server round-trip per click and the hover cursor outright. The lever if density ever bites is the zoom-dependent simplification the server already applies, not the renderer | §8.8 |
| LIM-F13 | `SettingsView` (`/settings`) covers exactly `storage.Settings` — pagination/list caps, geometry simplification bounds, tile cache lifetime, the shared metadata/schema cache TTL. `sources.maxSizeBytes`/`allowedExtensions` and, since TODO-17, the request body cap, the per-request timeout and every LRU cache's size (`config.SettingsConfig`) stay in `config.yaml`, read once at boot (`internal/config`) — none of them is on `storage.Settings`, so no route exposes them to patch. The two `sources` fields are the only ones a client can even read: `GET /sources/limits` publishes them read-only, so the upload states what it will refuse (§8.5) | Changing any of them still means editing `config.yaml` and restarting the server; lifting this needs a server-side chantier (moving a field onto `storage.Settings`) before the screen can gain it — for the guards TODO-17 just moved off it, that chantier would undo TODO-17's own point, so it is unlikely to be taken | `spec.md` §2.4, §2.5 |
| LIM-F15 | The table name a load is proposed (`utils/tableNames.ts`) is made free against the **imported** tables alone — the provenance index (`GET /tables/provenance`), which holds no derived table | A suggestion can collide with a table created by `/derive`, and the server accepts it: nothing is unique server-side (back LIM-23). The user sees the name before confirming and can change it. Checking against the whole catalogue would mean paging every table on a screen that is about files | §8.5 |
