# Darow — Identified debt (Go server)

> **Role** — the chantiers to run on the Go server: gaps between [spec.md](spec.md) and the code,
> structural debt, non-blocking fixes. Each row is work engaged or to be engaged, not a tolerated
> exception. What blocks a use goes to [blockers.md](blockers.md); what is accepted and will not be
> fixed to [limitations.md](limitations.md); what is not decided yet to
> [improvements.md](improvements.md).
>
> Vue 3 UI: [../front/todo.md](../front/todo.md) · Project:
> [../project/todo.md](../project/todo.md).

Each entry carries a stable identifier (`TODO-n`); a retired identifier is never reused.

**How much to write.** An entry may be long. Detail is welcome here — it is what makes the chantier
implementable months later, by someone with no memory of the audit that found it: name the files and
the symbols concerned, say what to change and in what order, state the constraints and invariants to
respect, and record the trap that produced the gap. Naming what exists is part of that: an
interface, a type, a method, a package are cited by name — that is a pointer into the code, not
code. Cite the file and the symbol, never a line number: it is stale the next time anyone touches
the file, and a wrong line sends the reader to the wrong place with confidence. A symbol is found by
search and stays true. What stays out is **code itself**: no snippet, no full signature, no diff.
Write the instruction, not the patch — the code is written later, against the code as it is then.

**Order of work.** TODO-8, TODO-13, TODO-10 and TODO-11 are done, from the plan established by the
audit of 2026-08-06 (which took up every lead `improvements.md` held: IMP-1 through IMP-7 became
TODO-9 through TODO-15, leaving that file empty). TODO-14 remains, the last of the plan: it is the
largest single chantier here, it is additive, and it is the only one whose shape is still partly
open.

**The tiles chantier** (TODO-24, TODO-23, TODO-22) came out of the audit of 2026-08-09, against
OGC API - Tiles Part 1: Core (OGC 20-057). Its three entries are ordered: the index range check
(TODO-24) and the layer name (TODO-23) are each worth doing on their own and are both prerequisites
of the OGC facade (TODO-22), which cannot publish a layer descriptor for a layer called `layer`, nor
honour the standard's error contract without a range check. TODO-22 is additive: no existing route,
response or parameter changes, so it can land whenever the two small ones have.

**Front counterpart.** TODO-14 has a matching chantier in [`../front/todo.md`](../front/todo.md)
(TODO-F37), which must not be started before its server side exists.

**The per-table settings chantier is done** (formerly TODO-18 → TODO-21): a table's own storage
override (`table_settings`, §4.10), its resolution against the global row (`TableSettingsService`,
§5.8.1), its REST surface (§6.1's **Tables**/**Settings** endpoint tables), and the coordinate-decimals
field, global and per table (§2.5.1, §4.7). Front counterpart done too (`../front/todo.md`
TODO-F41 → TODO-F43). It shipped ahead of TODO-16 rather than after it, by scope decision: the
per-table surface carries no bounds/units descriptor either, same as the global one — TODO-16 below
now covers both.

**Order of the settings chantier, across both sides.** The runtime-editable settings (§2.5) are the
one subject open on the server and on the UI at the same time, and the order between the two halves
was not free. `blockers.md` BLK-1 — the bounds, now in `internal/settings.Validate` — is done. The
UI's independent half is done too: what it stated about fields that already exist is corrected
(`../front/blockers.md` BLK-F1 and BLK-F2, both resolved) and the wording half of
[`../front/todo.md`](../front/todo.md) TODO-F39 (display unit, the meaning of `0`) is in place. The
decision that had to be taken **before** TODO-16 — which fields survive on `PATCH /api/v1/settings`
at all, and which move elsewhere — is taken and implemented: the reshaping (formerly TODO-17,
IMP-8/IMP-10/IMP-11/IMP-12 together) landed on both sides — server settings surface down to ten
fields (§2.5), the four moved guards now in `config.Config` (§2.4), and the front's own half
(formerly TODO-F40, `../front/todo.md`) followed it, `SettingsView`'s *Avancé* section included. What
remains is TODO-16 alone: publish a bounds/units descriptor for that ten-field surface, then the
bounds half of `../front/todo.md` TODO-F39 — the whole point of that chantier is that a bound lives
in one place and is read from there, so writing it on the screen before the API serves it re-creates
exactly the drift it exists to end.
