# CLAUDE.md

## Purpose

GeoAPI — a Go cartographic server backed by DuckDB (spatial extension). Serves sources, tables,
rows, MVT tiles, and SQL-derived tables over a REST API, plus a Vue3 admin UI embedded in the
binary.

## Repo map

-   `cmd/server` : entrypoint (`main.go`) — loads config, opens DuckDB, wires services, router, UI
-   `internal/config` : YAML config (`config.yaml`), defaults, `--workdir` flag override
-   `internal/storage` : storage-layer interfaces (`MetadataManager`, `TableManager`,
    `GeoTableManager`, `TableCreator`), `validateIdentifier`, `BuildFilter`, and `mocks/` for tests
-   `internal/storage/duckdb` : `Adapter` implementing the storage interfaces on DuckDB (writes
    serialized through `writeMu`, RTREE spatial indexing, MVT tiles, CTAS-based table creation)
-   `internal/service` : `TableService` (metadata cache, CRUD, `/derive`), `SourceService`
    (workDir scan/load), `GeoService` (tile cache keyed on table `UpdatedAt`)
-   `internal/router` : `chi` router, HTTP handlers, Swagger annotations, `/ui` SPA mounting
    (`webui.go`)
-   `internal/webui` : `go:embed` of the Vue3 UI's production build (`dist/`) — generated by
    `mise run ui-build`, never hand-edited; `dist/index.html` is a tracked placeholder until built
-   `web` : Vue3 + TypeScript + Tailwind admin UI (Vite). `src/client/` is a typed REST client
    (`http.ts`, `tables.ts`, `sources.ts`, `geo.ts`) kept separate from `src/views/`/`src/components/`
    — app code always goes through the client, never raw `fetch`. Built output goes straight to
    `internal/webui/dist` (see `vite.config.ts`), not `web/dist`
-   `docs/spec.md` : architecture and contracts of the current code, code-free, written to be read
    by an agent — the code is the source of truth, this describes it; `docs/audit-go.md` : Go code
    health, known defects, priorities; `docs/plan-repository-metadata.md` /
    `docs/plan-repository-data.md` : twin planned refactors introducing repositories for the
    catalogue (`metadata`) and for the data tables it references, run in parallel.
    `docs/docs.go`/`swagger.json`/`swagger.yaml` : generated by
    `swag init` (see Commands) — never hand-edit these

## Rules

-   Instructions describe and must describe (if updated) the state of the related code. It does not
    contain information about the past or old choices.
-   Before any Go change, follow the `go-implementation` / `go-testing` skills.
-   Never launch dev processes (`go run`, `mise run run-dev`, `mise run ui-dev`, `npm run dev`) on
    your own initiative — ask the user to run them, or confirm first.
-   Before any Vue3 changes, follow the `vue3-implementation` skill.
-   Never verify UI changes yourself via a browser or browser-automation tool — build/type-check
    (`mise run ui-build`) and let the user verify visually.
-   Prefer shared
    composables/components, except where a piece is genuinely substantial 
-   UI style: simple, uncluttered, professional — Tailwind utility classes, neutral palette, no
    component-library dependency. Shared pieces are pulled out once they're genuinely substantial
-   Git commands that change state (`commit`, `push`, `checkout`, `merge`, `rebase`, `reset`,
    `stash`, `worktree add/remove`, `branch -D`, ...) are forbidden unless explicitly requested.
-   Every new/changed struct, interface, method, or handler ships with its test in the same change
    changes do not need accompanying vitest tests unless explicitly asked for.
-   Any SQL identifier (table/column) interpolated into a query must go through
    `storage.ValidateIdentifier` first; values are always bound parameters, never interpolated.

## Commands

-   `mise run test` — run all Go tests
-   `mise run test-race` — run tests with the race detector
-   `mise run lint` — `go vet` + `gofmt -l .`
-   `mise run docs` — regenerate Swagger docs (`docs/docs.go`) from handler annotations
-   `mise run ui-install` / `ui-build` / `ui-dev` — web UI deps / production build (into
    `internal/webui/dist`) / Vite dev server
-   `mise run ui-lint` / `ui-test` — eslint / vitest for the web UI
-   `mise run build` — build the server binary (regenerates docs and UI first)
-   `mise run run-dev` — run the server against `config.yaml` (regenerates docs and UI first)
-   CI (`.github/workflows/ci.yml`) runs `go vet`/`gofmt`, `go test -race`, `ui-lint`/`ui-test`/
    `ui-build` (via `vue-tsc`/`vitest`/`vite`), and a Docker image build on every push/PR
-   `Dockerfile` — multi-stage build (UI → Go binary → slim runtime image); see also
    `.dockerignore`
